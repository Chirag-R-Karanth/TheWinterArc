# Phase-wise implementation
Execute in order; parallelize independent tasks only after foundation contracts stabilize. Do not mark a gate complete without evidence.

- Phase 00: [Audit](phases/PHASE_00.md) — Audit and feasibility records with evidence; preservation plan; approved architecture conflicts resolved.
- Phase 01: [Foundation](phases/PHASE_01.md) — Fixture import persists across restart; duplicate import and rollback tests pass; isolated restore verified.
- Phase 02: [Acquisition](phases/PHASE_02.md) — At least one real import verified if user supplies data; otherwise mark gate blocked. No fake connection states.
- Phase 03: [Core analytics](phases/PHASE_03.md) — Hand-calculated fixtures match; real data renders where available; missing states verified.
- Phase 04: [Advanced analytics](phases/PHASE_04.md) — Formula and lag tests pass; uncertainty, sample counts and limitations visible.
- Phase 05: [Lifestyle](phases/PHASE_05.md) — No redundant logging; import coverage and photo locality verified.
- Phase 06: [Refinement](phases/PHASE_06.md) — Exports match source data; keyboard/reduced motion verified; measured performance recorded.
- Phase 07: [Release](phases/PHASE_07.md) — All applicable acceptance gates evidenced; unresolved blockers listed; no unsupported completion claims.
