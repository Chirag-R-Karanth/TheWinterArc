# Security and recovery
Bind backend to loopback; same-origin UI, strict CORS and host validation, CSRF protection for mutations as appropriate. Parameterized SQL, validated uploads, path traversal and archive extraction defenses, size limits, redacted logs. OAuth least privilege, token refresh, Linux keyring; no secrets in source. .env.example placeholders only. No telemetry.
Use XDG paths outside Git for database, raw archive, photos, credentials and backups. SQLite foreign keys, transactions, WAL where appropriate, integrity checks and versioned migrations. Before migration create verified backup; test rollback or restore on a copy.
Backups: SQLite online backup API or equivalent consistent snapshot, raw files/photos manifest, checksums, atomic creation, retention, scheduled local snapshots and restore verification. Include privacy exclusions explicitly in manifest. Test restore into isolated directory before replacing live data. Export open formats. Optional encrypted remote backup only with explicit authorization; GitLab/Codeberg not for plaintext health data. Document key recovery and never commit credentials or private artifacts.
